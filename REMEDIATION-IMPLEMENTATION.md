## 1. Goal

## 2. Accepted root causes

From the Final Convergence Audit; refinements from the Design Review are normative.

- **RC-1 Authorization identity.** Approval is keyed by the caller-provided `callId` (`action-policy-guard/src/index.ts:65,77` — `Map<string,true>`), not bound to tool/args/session/agent/scope, and never consumed. Evidence: E1, E16, E17, E31.
- **RC-2 Sandbox authority ownership.** The caller controls the final authority through two unprotected entry points: the optional `sandboxPolicy` parameter (`fs/src/index.ts:227`, `bash-sandbox/src/index.ts:84-90`) and the unproven explicit `SandboxPolicyRequest.mode` override in `sandboxPolicy.resolve()`. Evidence: E7, E15. (Design Review widening: the `mode` override is part of this root cause, not a separate one.)
- **RC-3 Missing/corruption modeled as shorter valid state.** JSONL scanner hides the corruption `issue` field (`session-persistence-jsonl/src/format.ts:352-377`); `load()` synthesizes closers over a truncated prefix (E27); telemetry cursor skips failed records (E3); projection lost-update clears dirty state (E10). Invariants are blind to consistent loss.
- **RC-4 Canonical seq over-sharing.** `seq` serves durable truth, model-visible derivation, `sourceEventSeqs` references, SDK wire, and snapshot expectations; `ignorable` events still occupy seq. (Design Review evidence correction: top-level `seq`/`seq0` are already scrubbed by `acp-snapshot/src/normalize.ts:22-24`; drift comes from new event rows, event-sequence assertions, and embedded absolute seq references like `sourceEventSeqs`.)

## 3. Architectural invariants

Must never be broken by any PR. Each maps to a Design Review decision.

- A1 Each side-effectful execution consumes at most one `AuthorizationGrant` whose `OperationIdentity` matches the execution exactly (tool name, args digest, session, agent, scope, execution attempt).
- A2 A consumed grant cannot authorize a second execution.
- A3 `AuthorityContext` (resolved sandbox authority) can only be minted by `SandboxPolicyService`; callers submit requests, never authorities.
- A4 One tool call produces at most one `approval/asked` + `approval/decided` pair; denial from any decision source wins (deny > ask > allow), ask prompts exactly once through `ToolRuntime.serviceAsk()`.
- A5 Cancellation terminates the authorization lifecycle promptly (settles `cancelled`, unblocks turn end and fiber disposal) — guard path must pass `exec.signal`.
- A6 Every `approval/decided: allowed-once` has exactly one terminal disposition carrying the same `operationId` (executed or not-executed with reason), verifiable after restart.
- D1 `load()` snapshots carry `integrity: intact | repaired | unknown`; `repaired` is published only by an atomic repair transaction.
- D2 Committed-region corruption is never presented as a normal short log.
- D3 After crash/restart, unknown completeness is never marked `intact`.
- D4 The durable log is the only canonical source; projections/telemetry never feed recovery.
- E1 Per-session projection writes are serialized (single-flight with tail reset); a later cut never loses to an earlier cut.
- E2 Cache rows never carry a seq higher than the events they reflect.
- E3 Cache is never recovery authority.
- V1 New `SessionEventMap` members land with their fixture updates in the same PR; `SESSION_FORMAT_VERSION` bumps when old runtimes cannot interpret the log with full semantic correctness.
- T1 Every A/D/E invariant has at least one adversarial negative test that fails without its fix.

## 4. Accepted design decisions

Normative. Source: Final Remediation Plan sections E–K as corrected by the Design Review sections C–L. Where they conflict, the Design Review wins.

1. **Authorization**: `OperationIdentity` (module-private monotonic `operationId` + registry-minted `ToolExecutionToken` + callId + tool name + args digest + session/agent/scope + parent provenance), `AuthorizationGrant` one-shot consumed by membership check, bound to the **execution attempt** (not tool call, not side-effect operation). argsDigest is an audit binding, not a replay mechanism. `parentToken` is provenance only — no automatic authority inheritance.
2. **Single approval point**: `ToolRuntime.serviceAsk()` is the only `approval.request()` caller. Pre-execute decisions are collected (deny > ask > allow); the `tools.guard()` monotonic fence runs after grant consumption and only denies. Cancellation is a distinct terminal outcome.
3. **Sandbox**: `effective = meet(deploymentCeiling, sessionPolicy, bounded escalation)` with deny-by-default for future dimensions; escalation names explicit dimensions and is authenticated by an approval decision recorded in `approval/decided`. `workspaceRoot` is part of the authority. The "tool requirement" term from the plan is removed (no such mechanism exists). A WeakSet membership check of policy-owner-minted authorities runs at every enforcing fs/shell backend entry — this is the runtime provenance boundary, and it protects against forged authority objects (attacker classes A/B/C), never against malicious in-process code (D). **PD-1 (decided): deployment policy is the hard ceiling (`maxMode`). PD-3 (decided): class C in scope via the WeakSet check.**
4. **Durability**: JSONL `commitRepair` must be **atomic replacement** (build valid prefix + recovered events + closers + `session/repaired` → temp file → fsync → rename → directory fsync). Truncate-then-append is REJECTED (recreates E27). `session/repaired` is a distinct diagnostic event, not folded into `interruptedTurnClosers`. `integrity` is derived from the scan; `intact` means parse-consistent (no checksums yet). `SESSION_FORMAT_VERSION` 0 → 1 ships in the same atomic PR as the new event.
5. **Projection**: per-session single-flight promise chain with tail reset covering ALL write paths (timer, count, turn/end, detach, cold write-back, public `write()`); detach enqueued and awaited; `put` re-checks session lifecycle/identity before publishing; dirty bookkeeping clears only after settlement.
6. **Prompt/resources**: NO unified token budget. Layered bounds: source-level byte caps at ingestion/sync (MCP description/schema), compaction runs inside a reserved allowance (PR-6 F1 remediation: the summarizer request carries its own hard UTF-8 byte allowance `summarizationMaxBytes`, default 8 MiB, refused before dispatch with `COMPACTION_BUDGET_EXCEEDED`), final assembly gets a byte ceiling that rejects only after compaction cannot reduce further, with a deliverable rejection. **F2 accepted deviation (option B, recorded)**: the final token estimate is an ADVISORY provider-agnostic fixed-density heuristic, never a provider token guarantee; the UTF-8 byte ceiling is the normative hard enforcement and `maxEstimateTokens` is an opt-in early heuristic trigger only.
7. **Events**: canonical seq stays unified (no second sequence). Fixture strategy: scrub volatile ids (already done), pin absolute seq only in dedicated reference-relationship unit tests, assert type sequences + adjacency in assembled snapshots.
8. **Telemetry**: stays best-effort at-most-once observability (documented limitation), not a durable ledger.
9. **DO NOT BUILD**: distributed consensus/version vectors/CRDT; full event-sourcing rewrite; durable telemetry queue/Kafka; cryptographic capability signing; universal policy DSL; a second guard layer; split canonical seq; sandboxPolicy compatibility shims; silent prompt truncation; MCP effects trust mechanism.

Unresolved — require a human. Do NOT choose silently.

This is explicitly NOT a malicious in-process security boundary: a truly malicious same-process plugin (class D, monkey-patching or direct service access) is outside this remediation's protection.

- **actual changes**:
  1. Per-session single-flight tail (`SessionWriteState {tail, queued, detached}` on the `dirty` map): every trigger (`turn/end`, count threshold, interval, retry, detach) enqueues on ONE ordered tail; at most one checkpoint write is in flight per session; each queued write snapshots the newest registry cut at its turn.
  2. Coalescing bound to cut time: `queued` means "scheduled, cut not yet taken" (cleared when the task starts, not when it settles). A trigger arriving mid-flight enqueues a follow-up task — the running cut can never include its events, so riding it would be a lost update.
  3. Tail never poisoned by rejections: `tail = next.catch(() => {})`, chained with `then(run, run)`; failures are contained per task (warn + `failures += 1` + bounded retry timer re-armed on the dirty counter).
  4. Detach = ordered final task: never coalesced, always last; its cut is captured SYNCHRONOUSLY in the `session/disposed` handler (the disposal cascade unregisters projection units concurrently with the queue drain — a task-time checkpoint would be empty); an empty captured cut skips the put instead of wiping the last good row.
  5. Lifecycle rechecks after every await gap: a non-final write whose session detached while it flushed stands down before the put (the ordered final task owns the last durable cut); `session/event` ignores post-detach events (no bookkeeping resurrection).
  6. Dirty semantics (P6): `markClean(session, covered)` retires only the pending events folded into the settled cut; mid-flight events stay pending for the follow-up task; failures/retries reset only on success; the interval timer is cleared only once nothing remains dirty, and its slot is vacated before firing so mid-flight dirty events can re-arm.

## 8. Decision log

Deviations from accepted design (§4) are recorded here BEFORE implementation. A major architecture deviation pauses the PR and is reported to the human.

- **D-1 (PR-6 F2 remediation, option B — human-authorized 2026-08-24)**: the accepted "provider-aware final token estimate" is implemented as a provider-agnostic advisory fixed-density heuristic (chars/4). Rationale: the repository holds no per-provider tokenizer data; fabricating provider coefficients would invent unvalidated tunables. The UTF-8 byte ceiling (`maxRequestBytes`, and now `summarizationMaxBytes` for the compaction reserve) is the normative hard enforcement; `maxEstimateTokens` remains an opt-in heuristic trigger. Implementation, design (audit G/L7 + §4.6), docs (estimate JSDoc, agent-loop README/JSDoc), and tests (token-meter F2 contract pin) are aligned on this contract.
- **D-2 (PR-6 F1 remediation)**: design element ② ("compaction 请求本身占预算 / runs inside a reserved allowance") is implemented as `BasicCompactionConfig.summarizationMaxBytes` — an independent hard UTF-8 byte allowance on the summarizer dispatch, default `8 * 1024 * 1024` (the reserve deliberately exceeds the default request ceiling so a surface the request path just refused can still be compacted). Deployment-tunable, positive-safe-integer validated, strict `>` predicate; a region that exceeds it fails the compaction transaction typed (`COMPACTION_BUDGET_EXCEEDED`) before any provider dispatch, leaving the recovery loop's bounded/typed termination intact.

## 9. Known residual risks

Actively accepted; do not silently upgrade.

- Telemetry at-most-once; first-delivery failure is permanently lost; cross-process cursor not persisted.
- `workspace-write` always includes `/tmp` and the platform temp dir (shared cross-session channel).
- Unflushed events are lost on hard crash (semantic checkpoints mitigate the two critical points).
- Historical sessions' integrity is permanently `unknown` (no retroactive checksums).
- cwd restore is path-based; symlink swap remains undetected (mitigation: display resolved root on resume).
- Malicious in-process plugins (class D) are not contained — requires process/syscall isolation (Landlock), out of remediation scope.
- SDK malformed frames are silently dropped (JSON-RPC allows ignoring unlinkable frames). The dropped-frame counter suggested during PR-5 was NOT part of the accepted PR-6 scope and was NOT added; PR-6 disposed only the throwing/rejecting notification-handler containment finding.
- In-line silent bit flips in JSONL are undetectable without per-record checksums (deferred).
- A failed FINAL (detach) projection-cache write has no retry budget (the session is gone); the cold-read ladder self-heals — fail-soft by design.
- PR-6: `maxEstimateTokens` ships unset — the fixed-density estimate (chars/4) is computed and exposed on `agent/request-budget`, but estimate ENFORCEMENT is opt-in; the hard `maxRequestBytes` byte ceiling is the shipped safety boundary. The estimate is a heuristic, never a provider guarantee.
